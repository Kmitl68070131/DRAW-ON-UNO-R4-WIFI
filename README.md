# 🎨 UNO R4 WiFi Pixel Studio

> 🖥️ เว็บแอปพลิเคชันสำหรับวาดภาพพิกเซลและควบคุม LED Matrix บน Arduino UNO R4 WiFi แบบ Real-time ผ่าน MQTT

สร้างภาพพิกเซลบนเว็บ ส่งภาพไปยังบอร์ด Arduino UNO R4 WiFi และแสดงผลบน LED Matrix ขนาด 12 × 8 จุด พร้อมระบบสื่อสารผ่าน MQTT เพื่อให้เว็บและบอร์ดแลกเปลี่ยนข้อมูลกันผ่านเครือข่ายอินเทอร์เน็ต

## 🕹️ วิธีเล่นและใช้งานเว็บ

### 1. เปิดหน้าเว็บ

เข้าเว็บไซต์ของโปรเจกต์ หากยังไม่ได้เผยแพร่ สามารถเปิดไฟล์ `index.html` ในเบราว์เซอร์เพื่อทดสอบส่วนหน้าบางส่วนได้ แต่การเชื่อมต่อ MQTT ต้องตั้งค่า broker และ WebSocket ให้ถูกต้องด้วย

### 2. เลือกพิกเซลที่ต้องการวาด

- 🖱️ คลิกช่องพิกเซลเพื่อเปิดหรือปิดไฟ
- 🎨 เลือกสีหรือเครื่องมือวาด หากหน้าเว็บรองรับ
- 🧹 ใช้ปุ่มล้างภาพเพื่อลบภาพเดิม
- 🔄 ใช้ปุ่มรีเซ็ตเพื่อกลับสู่สถานะเริ่มต้น หากมีปุ่มดังกล่าว
- 📤 กดปุ่มส่งภาพ หรือใช้โหมดส่งอัตโนมัติ หากหน้าเว็บรองรับ

### 3. เชื่อมต่อกับบอร์ด

ก่อนส่งภาพ ให้ตรวจสอบว่า

- บอร์ดเปิดใช้งานอยู่
- บอร์ดเชื่อมต่อ Wi-Fi สำเร็จ
- บอร์ดเชื่อมต่อ MQTT broker สำเร็จ
- เว็บเชื่อมต่อ MQTT ผ่าน WebSocket สำเร็จ หากเว็บใช้ MQTT โดยตรง
- ทั้งสองฝั่งใช้ topic เดียวกันสำหรับส่งภาพ

### 4. ดูผลลัพธ์บน LED Matrix

เมื่อบอร์ดได้รับข้อมูลภาพและแปลงข้อมูลเป็นรูปแบบที่ LED Matrix รองรับแล้ว ภาพจะปรากฏบนจอ LED Matrix ของบอร์ด

หากภาพไม่เปลี่ยน ให้ตรวจสอบ topic รูปแบบข้อมูล และขนาดภาพที่เว็บส่งมาเทียบกับโค้ด Arduino

### 5. แชร์ให้เพื่อนเล่น

หากเผยแพร่เว็บบน GitHub Pages หรือบริการโฮสต์เว็บอื่นแล้ว สามารถส่ง URL ให้เพื่อนเปิดได้

**ข้อสำคัญ:** การเปิดเว็บได้ไม่ได้หมายความว่าบอร์ดจะเชื่อมต่อสำเร็จโดยอัตโนมัติ บอร์ดและเว็บต้องเข้าถึง MQTT broker เดียวกันและใช้ topic ที่ตรงกัน

### อธิบายขั้นตอน

1. ผู้ใช้วาดภาพบนหน้าเว็บ
2. JavaScript แปลงภาพเป็นข้อมูลพิกเซล
3. เว็บส่งข้อมูลไปยัง MQTT broker
4. Broker กระจายข้อความไปยังบอร์ดที่ subscribe topic นั้นไว้
5. Arduino อ่านข้อมูลและแสดงผลบน LED Matrix
6. บอร์ดสามารถส่งสถานะกลับไปยังเว็บผ่าน topic อีกตัวได้ หากมีการเขียนระบบรับสถานะไว้

**Real-time ไม่ได้หมายถึงไม่มีความหน่วงเลย** ความเร็วขึ้นอยู่กับ Wi-Fi, broker, ขนาดข้อความ และการประมวลผลของเว็บกับบอร์ด

### ต้องต่อ LED Matrix เพิ่มหรือไม่?

**ไม่จำเป็น** หากต้องการใช้ LED Matrix ที่ติดตั้งมากับ Arduino UNO R4 WiFi อยู่แล้ว

หากต้องการต่อ LED Matrix ภายนอก ต้องตรวจสอบแรงดันไฟฟ้า ขาเชื่อมต่อ และไลบรารีที่เหมาะสมกับจอรุ่นนั้นแยกต่างหาก

### ต้องมีอุปกรณ์เพิ่มเติมหรือไม่?

สำหรับการวาดภาพบน LED Matrix ที่ติดตั้งมากับบอร์ด ไม่จำเป็นต้องมีเซนเซอร์ มอเตอร์ หรือวงจรขับ LED เพิ่ม

## 📚 ไลบรารีที่ใช้

### Arduino IDE

ติดตั้ง Arduino IDE จากเว็บไซต์ทางการ:

https://www.arduino.cc/en/software

### 1. Arduino UNO R4 Boards

ใช้สำหรับคอมไพล์และอัปโหลดโปรแกรมลงบอร์ด

**วิธีติดตั้ง**

1. เปิด Arduino IDE
2. เข้าเมนู **Tools → Board → Boards Manager**
3. ค้นหา `Arduino UNO R4 Boards`
4. กด Install
5. เลือกบอร์ด `Arduino UNO R4 WiFi`

### 2. WiFiS3

```cpp
#include <WiFiS3.h>
```

ใช้เชื่อมต่อ Wi-Fi ผ่านโมดูลไร้สายของ UNO R4 WiFi

โดยปกติไลบรารีนี้จะติดตั้งมากับแพ็กเกจบอร์ด Arduino UNO R4 ที่เหมาะสม ไม่จำเป็นต้องติดตั้งไลบรารีชื่อเดียวกันแยก หาก IDE พบไลบรารีอยู่แล้ว

### 3. MQTT

```cpp
#include <MQTTClient.h>
```

ใช้สื่อสารกับ MQTT broker

โค้ดที่ใช้ `MQTTClient.h` ควรตรวจสอบให้ตรงกับไลบรารี MQTT ที่ติดตั้ง โดยไลบรารี **MQTT จาก 256dpi** เป็นตัวเลือกที่ใช้ header ชื่อนี้

วิธีติดตั้ง:

1. เปิด Arduino IDE
2. เข้า **Sketch → Include Library → Manage Libraries**
3. ค้นหา `MQTT`
4. เลือกไลบรารีที่มีไฟล์ `MQTTClient.h` ตรงกับตัวอย่างโค้ด
5. กด Install

> หากขึ้น `MQTTClient.h: No such file or directory` ให้ตรวจสอบว่าเลือกไลบรารีถูกตัวแล้ว และไม่มีไลบรารี MQTT หลายตัวที่ชนกัน

### 4. Arduino_LED_Matrix

หากโค้ดใช้ LED Matrix ในตัว ให้ตรวจสอบว่ามีไลบรารี `Arduino_LED_Matrix` ที่รองรับบอร์ดและเวอร์ชัน Core ที่ใช้อยู่

ตัวอย่าง:

```cpp
#include "Arduino_LED_Matrix.h"
```

ไลบรารีและ API ที่ใช้แสดงภาพต้องตรงกับโค้ดจริงในโปรเจกต์

### ไลบรารีฝั่งเว็บ

หากหน้าเว็บใช้ HTML, CSS และ JavaScript ปกติ จะไม่จำเป็นต้องติดตั้งไลบรารีเพิ่มเพื่อเปิดหน้าเว็บ

แต่ถ้า JavaScript เชื่อมต่อ MQTT ผ่าน WebSocket โดยใช้ไลบรารี เช่น MQTT.js ต้องมีการโหลดไลบรารีดังกล่าวในหน้าเว็บด้วย และต้องตรวจสอบเวอร์ชันกับ URL ที่ใช้งานจริง

## 🚀 เริ่มต้นใช้งาน

### ขั้นตอนที่ 1: เตรียมโค้ด

ดาวน์โหลดหรือ Clone Repository จาก GitHub แล้วตรวจสอบว่าไฟล์เว็บและไฟล์ `.ino` อยู่ในตำแหน่งที่ถูกต้อง

### ขั้นตอนที่ 2: ตั้งค่า Arduino IDE

1. ติดตั้ง Arduino IDE
2. ติดตั้งแพ็กเกจ Arduino UNO R4 Boards
3. ติดตั้งไลบรารี MQTT ที่ตรงกับ `MQTTClient.h`
4. ตรวจสอบไลบรารี LED Matrix ที่โค้ดเรียกใช้
5. เลือกบอร์ด `Arduino UNO R4 WiFi`
6. เลือกพอร์ต COM ที่ตรงกับบอร์ด

### ขั้นตอนที่ 3: ตั้งค่า Wi-Fi และ MQTT

เปิดไฟล์ `.ino` แล้วแก้ค่าต่าง ๆ ให้ตรงกับเครือข่ายและ broker ที่ต้องการใช้งาน โดยดูรายละเอียดในหัวข้อ [จุดที่ต้องแก้ไขในโค้ด](#️-จุดที่ต้องแก้ไขในโค้ด)

### ขั้นตอนที่ 4: อัปโหลดโปรแกรม

1. เชื่อมต่อบอร์ดกับคอมพิวเตอร์ด้วยสาย USB-C
2. เลือกบอร์ดและพอร์ตให้ถูกต้อง
3. กด Verify เพื่อตรวจสอบโค้ด
4. กด Upload
5. เปิด Serial Monitor เพื่อตรวจสอบสถานะ

หากใช้ `Serial.begin(115200);` ให้ตั้ง Baud Rate ใน Serial Monitor เป็น `115200` เช่นกัน

### ขั้นตอนที่ 5: เปิดเว็บและทดสอบ

เปิดหน้าเว็บ ตั้งค่า MQTT WebSocket ให้ตรงกับ broker จากนั้นทดสอบส่งภาพขนาด 12 × 8 จุดไปยังบอร์ด

## 🔌 วิธีต่อและตั้งค่าบอร์ดเอง

### กรณีใช้ Arduino UNO R4 WiFi ของตัวเอง

ไม่จำเป็นต้องดัดแปลงวงจร LED Matrix ในตัว เพียงทำตามขั้นตอนต่อไปนี้

1. ต่อสาย USB-C เข้ากับบอร์ด
2. เปิด Arduino IDE
3. เลือก `Arduino UNO R4 WiFi`
4. เลือก COM Port ที่ถูกต้อง
5. ใส่ Wi-Fi SSID และ Password ของเครือข่ายที่จะใช้
6. ตั้งค่า MQTT broker และ topics
7. อัปโหลดโค้ด
8. เปิด Serial Monitor เพื่อตรวจสอบการเชื่อมต่อ

### ถ้าใช้ Wi-Fi คนละเครือข่าย

แก้เฉพาะข้อมูล Wi-Fi ให้ตรงกับเครือข่ายใหม่

```cpp
const char WIFI_SSID[] = "YOUR_WIFI_NAME";
const char WIFI_PASSWORD[] = "YOUR_WIFI_PASSWORD";
```

เปลี่ยนค่า `YOUR_WIFI_NAME` และ `YOUR_WIFI_PASSWORD` ให้เป็นค่าจริง โดยไม่ต้องใส่เครื่องหมายวงเล็บมุม

ตัวอย่างรูปแบบ:

```cpp
const char WIFI_SSID[] = "MyWiFi";
const char WIFI_PASSWORD[] = "MyPassword";
```

เครือข่ายของมหาวิทยาลัย หอพัก หรือองค์กรบางแห่งอาจต้องล็อกอินผ่านหน้าเว็บ มีระบบยืนยันตัวตน หรือมีนโยบายจำกัดอุปกรณ์ IoT ทำให้การเชื่อมต่อจากบอร์ดไม่สำเร็จ แม้คอมพิวเตอร์จะใช้งาน Wi-Fi ได้ตามปกติ

### ถ้าต้องการใช้บอร์ดคนละตัว

สำหรับบอร์ด UNO R4 WiFi อีกตัว โดยทั่วไปสามารถใช้โค้ดเดียวกันได้หากตั้งค่าบอร์ดและไลบรารีตรงกัน แต่ต้องตรวจสอบว่า

- บอร์ดรุ่นที่เลือกตรงกับฮาร์ดแวร์
- Wi-Fi เชื่อมต่อได้
- Broker และ port เข้าถึงได้
- Topics ตรงกับเว็บ
- ข้อมูลภาพมีรูปแบบและขนาดที่โค้ดรองรับ

หากมีหลายบอร์ดที่ subscribe topic เดียวกัน ทุกบอร์ดอาจได้รับคำสั่งภาพเดียวกัน เว้นแต่จะแยก topic ตามอุปกรณ์

### 1. Wi-Fi SSID และ Password

ค้นหาส่วนตั้งค่า Wi-Fi ในไฟล์ `.ino`

```cpp
const char WIFI_SSID[] = "YOUR_WIFI_NAME";
const char WIFI_PASSWORD[] = "YOUR_WIFI_PASSWORD";
```

แก้เป็นชื่อและรหัสผ่านของเครือข่ายที่บอร์ดจะเชื่อมต่อ

**ข้อควรระวัง:** อย่าเผยแพร่รหัสผ่าน Wi-Fi จริงใน Repository สาธารณะ หากต้องการให้ผู้อื่นนำโค้ดไปใช้ ให้ใช้ค่าตัวอย่างแทนและอธิบายให้ผู้ใช้ใส่ค่าของตนเอง

### 2. MQTT Broker

ตัวอย่างการตั้งค่าที่พบในโค้ดโปรเจกต์:

```cpp
const char MQTT_BROKER_ADDRESS[] = "mqtt-dashboard.com";
```

หากต้องการเปลี่ยน broker ให้แก้เป็น hostname ของ broker ที่ใช้งานจริง และตรวจสอบ port, TLS และการยืนยันตัวตนให้ตรงกับบริการนั้น

อย่าเปลี่ยน hostname เพียงอย่างเดียว หาก broker ใหม่ต้องใช้ username/password หรือการเชื่อมต่อแบบ TLS

### 3. MQTT Topics

ตัวอย่าง topics ที่ใช้เป็นค่าตั้งต้นในโปรเจกต์:

```text
it68070131/arduino-uno-r4/send
it68070131/arduino-uno-r4/receive
it68070131/arduino-uno-r4/status
```

ความหมายที่แนะนำให้ใช้:

| Topic | หน้าที่ |
|---|---|
| `it68070131/arduino-uno-r4/send` | ส่งภาพหรือคำสั่งจากเว็บไปยังบอร์ด |
| `it68070131/arduino-uno-r4/receive` | ส่งข้อมูลจากบอร์ดกลับไปยังเว็บ |
| `it68070131/arduino-uno-r4/status` | ส่งสถานะออนไลน์หรือออฟไลน์ |

**สำคัญ:** ชื่อ topic ต้องตรงกันทั้งฝั่งเว็บและฝั่ง Arduino และความหมายข้างต้นต้องสอดคล้องกับการ `publish()` และ `subscribe()` ที่เขียนไว้จริงในโค้ด

หากต้องการแยกบอร์ดของแต่ละคน ให้กำหนด namespace ของตัวเอง เช่น

```text
pixel-studio/device-001/send
pixel-studio/device-001/receive
pixel-studio/device-001/status
```

แล้วแก้ topic ในทั้งสองฝั่งให้ตรงกัน

### 4. ขนาดภาพ

UNO R4 WiFi มี LED Matrix ในตัวขนาด 12 คอลัมน์ × 8 แถว รวม 96 พิกเซล

```text
กว้าง = 12 พิกเซล
สูง   = 8 พิกเซล
รวม   = 96 พิกเซล
```

หากหน้าเว็บสร้างภาพขนาดอื่น ต้องแปลงข้อมูลให้ตรงกับรูปแบบที่โค้ด Arduino รองรับก่อนส่ง

### 5. MQTT Port และการเชื่อมต่อ

อย่ากำหนด port โดยเดา ให้ตรวจสอบเอกสารของ broker ที่เลือกใช้ก่อน

- MQTT over TCP มักใช้ port `1883` สำหรับการเชื่อมต่อที่ไม่เข้ารหัส
- MQTT over TLS มักใช้ port `8883`
- MQTT over WebSocket ใช้ port และ path ตามที่ผู้ให้บริการกำหนด

เว็บเบราว์เซอร์ไม่สามารถเชื่อมต่อ MQTT ผ่าน TCP แบบปกติได้โดยตรง หากเว็บเชื่อมต่อ broker เอง ต้องใช้ WebSocket endpoint ที่ broker รองรับ

## 📡 การตั้งค่า MQTT

### หลักการทำงานของ MQTT

MQTT เป็นโปรโตคอลสื่อสารแบบ publish/subscribe ที่อาศัย broker เป็นตัวกลาง

- **Publisher:** ผู้ส่งข้อความ
- **Subscriber:** ผู้รับข้อความ
- **Broker:** เซิร์ฟเวอร์กลางที่รับและกระจายข้อความ
- **Topic:** ชื่อช่องทางสำหรับจัดหมวดหมู่ข้อความ

### การกำหนด topic ให้ตรงกัน

ตัวอย่างลำดับการทำงาน:

1. เว็บเชื่อมต่อ broker ผ่าน WebSocket
2. บอร์ดเชื่อมต่อ broker ผ่าน MQTT
3. บอร์ด subscribe topic สำหรับรับภาพ
4. เว็บ publish ข้อมูลภาพไปยัง topic นั้น
5. บอร์ดรับข้อความและแสดงผล

### รูปแบบข้อมูลภาพ

รูปแบบ payload ต้องตรงกับโค้ดจริงทั้งสองฝั่ง ตัวอย่างเช่น ระบบหนึ่งอาจส่งข้อมูลพิกเซลเป็นสตริง 96 ตัวอักษร โดยแต่ละตัวแทนสถานะเปิดหรือปิด แต่โปรเจกต์อาจใช้ JSON หรือรูปแบบอื่นได้เช่นกัน

**อย่าสมมติว่า payload เป็นสตริง 96 ตัวอักษรหรือ JSON โดยไม่ได้ตรวจสอบโค้ดจริง** หากรูปแบบไม่ตรงกัน บอร์ดอาจรับข้อความสำเร็จแต่ไม่แสดงภาพ

### ระบบสถานะ Online / Offline

หากต้องการให้หน้าเว็บแสดงสถานะบอร์ด ควรมีแนวทางดังนี้

1. บอร์ดส่งข้อความ heartbeat ตามช่วงเวลาที่กำหนด
2. เว็บ subscribe topic สถานะ
3. เว็บอัปเดตสถานะเมื่อได้รับข้อความ
4. หากไม่มี heartbeat เกินเวลาที่กำหนด ให้แสดงว่าอาจออฟไลน์
5. เมื่อเชื่อมต่อใหม่ บอร์ดควรส่งสถานะออนไลน์อีกครั้ง

การไม่พบข้อความใหม่ไม่ได้พิสูจน์ว่าบอร์ดปิดเครื่องเสมอไป เพราะอาจเกิดจากเครือข่ายขาดช่วงหรือ broker มีปัญหา

### ❌ 1. `WiFi.status()` แสดง `0` ซ้ำ ๆ

สถานะ `0` โดยทั่วไปหมายถึง `WL_IDLE_STATUS` ซึ่งเป็นสถานะที่กำลังทำงานหรือยังอยู่ในช่วงเชื่อมต่อ ไม่ใช่หลักฐานว่าเชื่อมต่อสำเร็จแล้ว

**วิธีแก้**

1. ตรวจสอบ SSID และ Password
2. ตรวจสอบว่าเครือข่ายรองรับการเชื่อมต่อของ UNO R4 WiFi
3. ตรวจสอบว่าต้องล็อกอินผ่านหน้าเว็บหรือไม่
4. ตรวจสอบข้อจำกัดของเครือข่ายองค์กรหรือมหาวิทยาลัย
5. แสดงค่า `WiFi.status()` และเวลาที่ใช้เชื่อมต่อใน Serial Monitor เพื่อวิเคราะห์เพิ่มเติม

### ❌ 2. MQTT error: `-2`

ความหมายที่แน่นอนขึ้นอยู่กับไลบรารีและเวอร์ชันที่ใช้ จึงไม่ควรสรุปจากเลข error เพียงอย่างเดียว

**ตรวจสอบตามลำดับ**

1. Wi-Fi เชื่อมต่อสำเร็จหรือยัง
2. ชื่อ broker ถูกต้องหรือไม่
3. Broker เปิดให้เชื่อมต่อจากเครือข่ายของบอร์ดหรือไม่
4. Port ถูกต้องหรือไม่
5. ต้องใช้ TLS หรือ username/password หรือไม่
6. Broker ยังทำงานอยู่หรือไม่
7. ไลบรารี MQTT ที่ใช้ตรงกับ API ในโค้ดหรือไม่

### ❌ 3. Serial Monitor แสดงตัวอักษรเพี้ยน

สาเหตุที่พบบ่อยคือ Baud Rate ไม่ตรงกัน

**วิธีแก้**

หากโค้ดใช้

```cpp
Serial.begin(115200);
```

ให้เลือก Baud Rate `115200` ใน Serial Monitor

หากยังมีปัญหา ให้ตรวจสอบการตั้งค่า Serial ในโค้ดและรีสตาร์ตบอร์ดหลังเปิด Serial Monitor

### ❌ 4. เว็บเปิดได้ แต่ส่งภาพไม่ได้

ตรวจสอบว่า

- WebSocket URL ถูกต้อง
- Broker รองรับ MQTT over WebSocket
- ใช้ `wss://` เมื่อหน้าเว็บอยู่บน HTTPS และ broker รองรับการเชื่อมต่อแบบปลอดภัย
- เว็บและบอร์ดใช้ topic เดียวกัน
- Browser Console ไม่มีข้อผิดพลาด
- Broker อนุญาตให้ client เชื่อมต่อและ publish ข้อความ

### ❌ 5. บอร์ด Online แต่ LED Matrix ไม่เปลี่ยน

บอร์ดที่เชื่อมต่อ MQTT ได้ไม่ได้หมายความว่าข้อมูลภาพถูกประมวลผลถูกต้องเสมอไป

ตรวจสอบ:

1. บอร์ด subscribe topic ที่ถูกต้องหรือไม่
2. Callback ได้รับข้อความหรือไม่
3. Payload ตรงกับรูปแบบที่โค้ดคาดหวังหรือไม่
4. ขนาดภาพเป็น 12 × 8 หรือถูกแปลงให้ถูกต้องหรือไม่
5. โค้ดเรียก API ของ LED Matrix ถูกต้องหรือไม่

### ❌ 6. GitHub Pages เปิดหน้าเว็บไม่ได้

ตรวจสอบว่า

- เปิดใช้ GitHub Pages แล้ว
- เลือก branch และโฟลเดอร์ถูกต้อง
- มีไฟล์ `index.html`
- ชื่อไฟล์และพาธตรงตามตัวพิมพ์เล็ก–ใหญ่
- ไฟล์ CSS และ JavaScript อ้างอิงด้วยพาธที่ถูกต้อง
- รอให้การ Deploy เสร็จสมบูรณ์แล้ว

### ❌ 7. คนอื่นเปิดเว็บได้ แต่ไม่เห็นบอร์ด

สาเหตุอาจเกิดจาก

- บอร์ดไม่ได้เชื่อมต่อ broker
- บอร์ดใช้ Wi-Fi ที่ไม่อนุญาตให้เข้าถึง broker
- เว็บกับบอร์ดใช้คนละ broker หรือคนละ topic
- ระบบสถานะยังไม่ได้เขียนหรือไม่ได้ส่ง heartbeat
- Broker ไม่อนุญาตให้ client ภายนอกเชื่อมต่อ

การเปิดเว็บสาธารณะไม่สามารถทำให้บอร์ดที่ปิดเครื่องหรือขาดการเชื่อมต่อกลับมา Online ได้เอง

### Wi-Fi Password

ห้ามใส่รหัสผ่าน Wi-Fi จริงลงใน Repository สาธารณะ ให้ใช้ค่าตัวอย่างในไฟล์ที่เผยแพร่ และใส่ค่าจริงในสำเนาโค้ดที่ใช้ภายในเครื่อง

หากเผลอเผยแพร่รหัสผ่านไปแล้ว ควรเปลี่ยนรหัสผ่านทันที การลบข้อความจากไฟล์ปัจจุบันไม่ได้รับประกันว่าค่านั้นจะหายจาก Git history

### MQTT Broker

Broker สาธารณะอาจอนุญาตให้ผู้ใช้รายอื่น publish หรือ subscribe topic เดียวกันได้ หากไม่มีการยืนยันตัวตนหรือการกำหนดสิทธิ์ที่เหมาะสม

เพื่อใช้งานจริง ควรพิจารณา:

- ใช้ broker ที่มีการยืนยันตัวตน
- เปิดใช้ TLS เมื่อรองรับ
- กำหนดสิทธิ์ publish/subscribe แยกตาม topic
- จำกัดอัตราการส่งข้อความ
- ตรวจสอบรูปแบบและขนาด payload ก่อนประมวลผล
- หลีกเลี่ยงการฝัง secret ลงใน JavaScript ที่เผยแพร่สู่สาธารณะ

**ข้อควรระวัง:** ข้อมูลที่ฝังในไฟล์ JavaScript ของเว็บสาธารณะสามารถถูกผู้ใช้เปิดดูได้ ไม่ควรเก็บ secret ที่ต้องปกปิดไว้ในไฟล์ดังกล่าว

## ❓ FAQ

### Q: ต้องใช้ Arduino UNO R4 WiFi เท่านั้นหรือไม่?

A: โค้ดส่วนที่ใช้ `WiFiS3` และ LED Matrix ในตัวออกแบบมาสำหรับ UNO R4 WiFi หากใช้บอร์ดอื่นต้องปรับส่วนเชื่อมต่อ Wi-Fi และส่วนแสดงผลให้ตรงกับฮาร์ดแวร์

### Q: ต้องต่อ LED Matrix เพิ่มหรือไม่?

A: ไม่จำเป็นสำหรับ LED Matrix ในตัวของ UNO R4 WiFi

### Q: ใช้งานโดยไม่มีอินเทอร์เน็ตได้หรือไม่?

A: หากเว็บและ broker อยู่บนเครือข่ายเดียวกัน อาจทำงานได้โดยไม่ต้องออกอินเทอร์เน็ต แต่ขึ้นอยู่กับตำแหน่งของ broker และการตั้งค่าเครือข่าย

### Q: เพื่อนสามารถเล่นจากบ้านคนละเครือข่ายได้หรือไม่?

A: ได้ หากเว็บถูกโฮสต์สาธารณะ และทั้งเว็บกับบอร์ดเชื่อมต่อ broker ที่เข้าถึงได้จากอินเทอร์เน็ตอย่างถูกต้อง

### Q: ถ้าเปลี่ยนชื่อ topic ต้องแก้ตรงไหน?

A: ต้องแก้ทั้งฝั่งเว็บและฝั่ง Arduino ในตำแหน่ง publish/subscribe ที่เกี่ยวข้องให้ตรงกัน

### Q: ทำไมภาพที่ส่งไปไม่ตรงกับ LED Matrix?

A: ให้ตรวจสอบลำดับพิกเซล วิธีจัดเก็บข้อมูล รูปแบบ payload และการแปลงข้อมูลก่อนแสดงผลบนจอ

### Q: จำเป็นต้องเปิด Serial Monitor ตลอดเวลาหรือไม่?

A: ไม่จำเป็นสำหรับการทำงานปกติ แต่มีประโยชน์มากในการตรวจสอบปัญหา Wi-Fi, MQTT และ payload ระหว่างพัฒนา
